# Aaron Alva Portfolio — CLAUDE.md

Single-page portfolio (`bunny-sysd.github.io/portfolio`) structured after activetheory.net (studied hands-on and with REA — see `RESTRUCTURE_PLAN.md` Part 9; **its structure and interaction patterns, never its code, shaders, models, font or copy**): one fixed WebGL stage with views that swap in place — home (a GPU particle core + credentials), a work carousel of glass cards orbiting the core, project detail (the card flies to the camera), and a frosted contact overlay — plus a terminal box as the cyber feature. Built on branch `at-structure`; the previous cloud-descent site (branches `cinematic-descent`/`at-polish`) is recoverable from git.

## Stack

- Vite **6** + **vitest 5**, a real ES module build — **npm-package Three.js (`three` ^0.186) imported from `src/`, not CDN scripts.** `vite.config.js`: `base: './'`, `build.outDir: 'docs'`, `test.include: ['tests/unit/**/*.test.js']`. No Lenis any more (removed with the scroll film).
- **The page doesn't scroll.** `body { overflow: hidden }`; views are fixed layers toggled by `is-active`/`inert`. Wheel, keys and swipes are read by `views.js` and turned into route changes or carousel steps (home ⇄ work at ~220 px of wheel, one carousel step per ~110 px with a 320 ms gap, ~260 px closes a project — "scroll to close").
- **Hash routing** (`router.js`): `#/`, `#/work`, `#/work/<id>`, `#/contact`. Hash, not path, because GitHub Pages with a relative base can't serve nested paths without a 404 trick. Legacy `#<case-id>` links map to that project's detail with its dossier open. Back/Forward work.
- `src/projects.js` is the single source of truth for project copy, tags and links — verbatim from the verified text; **no invented years/clients** (the AT-style meta line is category / stack instead).
- `src/tier.js` gates quality once at load into `low`/`mid`/`high` (`renderScale` 0.75 / 1 / 1.25 — the particles and card screens are crisp detail; and whether post FX runs).
- `playwright` drives all real-browser verification (`tests/e2e/*.mjs`), with real-GPU flags (`lib.mjs` `GPU_ARGS`); the no-WebGL case deliberately uses `--disable-webgl --disable-3d-apis`.
- Chrome DevTools MCP can develop a stuck profile lock across sessions ("browser is already running") — don't kill Chrome processes, fall back to Playwright.
- REA (morluto/rea) is installed only as a skill in `~/.agents/skills`, not as a Claude Code MCP server; its CLI (`npx -y rea-agents@6.5.0 analyze-javascript-application <dir> --json`) works without registration.

## File layout

- `index.html` — the only entry point: chrome (nav pill + credentials ticker), the four `<section class="view">`s, the terminal form, and the five case-study `<dialog>`s (unchanged dossiers). `<script type="module" src="/src/main.js">`.
- `src/`:
  - `main.js` — wiring and the single rAF loop: stage → world → post; router → views; terminal; dossiers (`initCaseStudies` with a no-op scroll). Precompiles **both** the scene (`renderer.compileAsync`, against the composer target) **and** the post chain (`post.precompile()`) before the first draw; drawing straight away linked shaders synchronously (~300 ms freeze). FPS watchdog: lower resolution → drop post (`data-quality`). Context loss toggles `no-webgl`. Dev-only handles: `window.__stage`, `__world`, `__fluidEnergy`.
  - `router.js`, `projects.js`, `views.js` (DOM side of the views: caption/detail rendering with `decodeText`, filters, all input, canvas-click picking, focus moves into the new view), `terminal.js` (commands answered from site data only; input is only ever written back via `textContent`; links come from data, never from input), `case-study.js`/`case-ids.js` (dossier dialogs; the router now owns their hashes), `contact.js` (mailto builder).
  - `scene/`: `stage.js` (renderer bootstrap + WebGL probe; `renderer.debug.checkShaderErrors` is **on only in dev** — reading info logs forces a sync GPU wait), `world.js` (scene graph + camera marks per view — home stands back down the tower corridor at z 30 with the core framed right of the copy, eased base position with pointer parallax added as a pure offset — adding it to the eased position compounded to a ~12-unit drift once; portrait screens get their own marks), `blackhole.js` (the centrepiece — replaced the 60k-point particle core: a **ray-traced Schwarzschild black hole**. Pipeline: backdrop (scene minus cards and lens) → `hole.render()` copies it into `hole.target` and traces a camera-facing disc over it — per pixel, a light ray integrated through the photon-orbit equation `a = -1.5·rs·h²·p/r⁵` inside a bounding sphere (140/96/56 steps by tier), collecting a volumetric accretion disk at each crossing of its plane (thin-disk temperature → blackbody colour, Doppler g³ beaming, gravitational redshift, ISCO inner edge, Keplerian-sheared fbm gas), and sampling the backdrop along the escape direction (bending eased out toward the disc rim so there's no seam). The main scene's `lens` mesh just blits `hole.target` (opaque, `depthTest: false`, renderOrder 1 so it draws over the water but writes depth so towers behind it are hidden); the glass cards refract `hole.target` too. The tracer is precompiled with `compileAsync` in main.js. The water's mirror hides the lens via a wrapped `onBeforeRender`. The centre light shaft was moved off-axis — lensed, it made a pale disc round the hole. 60 fps at 2560×1271 on an RTX 5060 Ti), `environment.js` (the scenery, all procedural: ~110 particle "server towers" with data bands climbing them, a clearing round the core and a corridor along +z that home → work flies up; a `Reflector` water floor with its own shader — calm ripple, reflections dimmed near the camera so they never sit loud under text, a faint grid, and vault rings; glyph pillars that fade in for work, placed behind/beside the ring only; additive light shafts. Point sizes are clamped to 1.5–4 px — unclamped, far towers vanished and near pillars ballooned), `cards.js` (glass cards: refract a half-res backdrop pass via `renderBackdrop()` — which hides the water so the mirror isn't rendered twice, double-sided, yaw = 0.3 × ring angle so side cards face the camera; the open card lerps in front of the camera, right of centre on desktop), `screens.js` (original Canvas2D motif per project), `post.js` + `fluid.js` (bloom → fluid pass → output → grain; the fluid pass does cursor fluid, the frosted nav corner, the detail/dive streak and the contact frost — full-frame here via `contactFull`, as a 12-tap jittered disc blur, since 4 fixed taps stamped ghost copies).
  - `widgets/` — `decode.js` (scramble-decode; always decodes the element's *current* text and cancels a run already in flight on that element — a cached text once showed the wrong project title), `boot.js` (load readout), plus the dossier widgets `phase-flow.js`, `commands.js`.
  - `styles/site.css` (everything outside the dossiers), `styles/case-study.css` (dossiers).
- `docs/` is gitignored build output, deployed by GitHub Actions on push to `main`.
- `.agents/mcp_config.json` is gitignored and holds a live-looking secret. Never `git add -f` it or echo it.

## Address-space layer (branch `address-space`)

The concept tying the site together: **the site is an address space you're scanning**, and each effect is a real security idea, not decoration. Researched from IPv4 census maps (CAIDA, Hilbert-curve layout), binary visualisers (binvis entropy colouring), hash avalanche demos, defence-in-depth diagrams and SOC threat maps.
- `src/hilbert.js` — `d2xy`/`xy2d`/`toIPv4` (order-16 Hilbert map of the screen onto the 2^32 IPv4 space; plain arithmetic so it stays exact past 32-bit ints). Unit-tested.
- `scene/netfloor.js` — one order-7 Hilbert curve (16384 cells) on the water as a single `THREE.Line`; scan packets crawl it, a few 16-cell blocks burn amber like high-entropy regions; the stretch round the core lights up in work ("in scope").
- `scene/perimeter.js` — defence in depth: hostile probes (rose) arc in from the forest and stop at a shell round the core that only shows where it's hit (impact ring over a lat/long lattice). Probes are closed-form in the vertex shader; the CPU runs the same formula to place the 12 newest impacts and to count `blocked` for the HUD (labelled **sim** on the page — it's a simulation, never present it as real traffic). Fades while a project is open.
- `widgets/avalanche.js` — view changes run a hash-avalanche wave: a 2D-canvas bit-cell front from the last pointerdown, ~half the cells it crosses flip (reseeded per wave). Plain canvas so it works on every tier and without WebGL; off under reduced motion.
- `widgets/sigil.js` — real SHA-256 (WebCrypto) of a title drawn as a 16×16 = 256-bit grid; changing project flips the differing bits in a cascade. Identity sigil top-left is `sha256("Aaron Alva")`; the caption's is the project title's. No `crypto.subtle` (insecure context) → no sigil, nothing breaks.
- `widgets/probe.js` — fine-pointer reticle (native cursor kept) reading the IPv4 address under the pointer; over a control it locks to the bounds and runs a zero-trust "auth… → ✓ verified" beat. Hidden while a dialog is open.
- `widgets/sound.js` — generative WebAudio (drone + step ticks + avalanche blips), off by default, remembered in localStorage, never auto-starts without a gesture.
- Terminal: `hash <project>` prints the full digest; Ctrl/⌘+K or `/` summons it from any view (`html.term-summoned` shows it on home).
- Round 4: the centre is a **black hole = sinkhole** (DNS-sinkhole idea: hostile traffic routed into a void). `perimeter.js` no longer has a shield — probes accelerate in on curved approaches and fade at the horizon; HUD reads "Sinkhole active · N probes swallowed · sim". `renderBackdrop()` now runs every frame (the lens needs it), with water included so the lens rim matches the frame, at full res except on the low tier (`cards.setSize(..., scale)`).
- Round 2: `scene/census.js` — a far "census sky" (256² order-8 Hilbert layout allocated in CIDR-sized runs, a DataTexture with the Hilbert index in G/B so a scan sweeps it in address order); keep it faint — at full strength it washed the whole forest out. The world tints to the focused project's `hue` (floor scope, shield, census scan; cards get a scan line in their own hue). `post.js` film pass has `uGlitch` (slice jumps + RGB split) for ~0.3 s after a view change. `widgets/boot.js` is now a stylised TLS-handshake readout ending "Channel secure", and the first frame runs an avalanche from the centre. `widgets/cipher.js` encrypts the contact message live with real AES-256-GCM under a throwaway key — the label says it's a preview and the mail app sends the plain message; keep that label. Terminal: `nmap` (the site's views as ports) and `traceroute <project>` (flies home → work → project, no fake latencies).
- Round 3 (cinematic): an **establishing shot** — once per session on home, `world.playIntro()` rides two Catmull-Rom splines (camera + an aim sampled slightly ahead) from high over the address space down onto the home mark in 6 s, letterboxed 2.39:1 (`.letterbox`, `html.is-intro`), home copy and chrome held back until it lands; any wheel/pointer/key/touch cuts it and the camera glides from where it is; never under reduced motion or on deep links. `lib.mjs` marks it seen for every suite unless a page asks `{ intro: true }`. **Dolly zoom** on opening/closing a project: fov += 24·sin(π·open) while the open card's distance is scaled by tan(markFov/2)/tan(fov/2) so it holds its size and the world stretches. **Anamorphic streaks** (16 horizontal taps over a 0.72 threshold) in the film pass. A **hand-held camera** breath (two slow sines, a few cm), off under reduced motion.
- `tests/e2e/address.mjs` covers all of it in both motion settings, plus a SwiftShader run that must land on the low tier (no post) and keep working (~27 fps CPU-only). `tests/e2e/_shots.mjs [WxH] [prefix]` is a dev helper for eyeballing screenshots.

## Fallbacks

- **No WebGL**: `createStage()` returns `null`, `html.no-webgl`; the DOM carries the whole site over a CSS radial backdrop — the work caption with its arrows and Open button, details, contact. Same class while the context is lost.
- **No JavaScript**: home (name + three credentials) shows and reads; the rest needs JS.
- **`prefers-reduced-motion`**: no fluid splats, streak, decode, ticker or cue animation; core/card motion held still (`uTime` 0); view changes are short fades and eased values snap. Views, routing, filters and the carousel all still work. Aaron's own PC has animations off, so he sees this version by default (see memory).
- All three, plus context loss/restore, are covered by `tests/e2e/fallbacks.mjs`.

## Commands

- `npm run dev` — Vite dev server (`127.0.0.1:5173`)
- `npm run build` — outputs to `docs/`
- `npm test` — vitest over `tests/unit/` (router, tier, contact). **Needs Node ≥22.12 locally**; CI (Node 20) only builds, so run it yourself.
- `npm run e2e` — `site.mjs` (views, routing, carousel, filters, detail, contact, terminal incl. an HTML-injection check, Back, decode, fluid energy, contrast, phone swipes; both motion settings), `case-study.mjs`, `fallbacks.mjs`, against the dev server.
- `node tests/e2e/perf.mjs` — production load check (longest main-thread task < 250 ms); needs `npm run build` + `npx vite preview --port 4173`. Dev builds keep shader error checks on, so `site.mjs` only holds dev to a looser bound.
- `node tests/e2e/_gpu.mjs [WxH]` — GPU ms of the scene pass per view (dev server). At 1920×1080 high tier it's < 0.5 ms; the post chain is most of the frame.
- No lint script.
